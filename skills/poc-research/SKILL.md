# poc-research

Question: "$ARGUMENTS". Never use em dashes. If the question is empty, reply only with `NEEDS INPUT: give me the question` and stop.

**Prerequisites.** Before anything else, run `sh "${CLAUDE_PLUGIN_ROOT}/scripts/check-prereqs" poc-research git python3:optional` as a command on its own, never joined to another with `;` or `&&`, and read its output. If the last line is `prereqs: missing ...`, print each `MISSING:` line as it is, change nothing, and end with `Next: install what is missing, then run /spike-loop:poc-research again`. Print any `skipped:` line and leave out the step that needs that tool. If the check cannot run (refused, not found, no POSIX shell, or a `prereqs: usage error` line), say so in one line and continue: a command that needs a missing tool will fail with its own error. This check covers any agent this command starts: when you brief an agent, say "prerequisites checked".

**Paths.** Every path in this command is relative to the repo root. Find the root with `git -C "<target>" rev-parse --show-toplevel`, where `<target>` is the project path given in the arguments if this command takes one and one is given, otherwise the directory the session was started in (an agent uses the repo root named in its brief, and outside a git repository the root is `<target>`). The shell can be reset to the start directory between calls, and is in an agent, so run a command that needs the working directory (it uses a relative path or runs a script there) as `cd "<root>" && <command>`, run git as `git -C "<root>" <subcommand>`, and run any other command as it is (such as `date`, a script by its absolute path, or `chmod` or `tail` given a `<root>/<path>`), unless a step names another directory. File tools (Read, Write, Edit, Glob, Grep) resolve a relative path against the start directory, so give them `<root>/<path>` in full, and use them to check, read and list files. If a shell command or tool is refused (for example `cd ... was blocked`) because the repo root is outside the directories this session may use, do not work around it: say so (an agent reports it and stops), and tell the user to start the session at the repo root or run `/add-dir "<root>"`. A relative project path in the arguments is relative to the directory the session was started in, only to find the root. Everything else is relative to the root.

**Docs folder.** Check these four paths, relative to the repo root, by reading each with the Read tool (it needs no `cd`, a missing file is just an error, and Glob can skip gitignored files, which `poc-spec/` often is): `poc-spec/POC.md`, `poc-spec/LOG.md`, `POC.md`, `LOG.md`. If files exist only under `poc-spec/`, the docs folder `<docs>` is `poc-spec`. If they exist only at the root, `<docs>` is `.` (an older PoC, use it as is). If files exist in both places, stop, say the PoC is half-migrated, name the files, and ask which to keep (an agent reports this and stops). If none exist, follow the command's own step. `<docs>/POC.md` means `poc-spec/POC.md` or `POC.md`, and likewise `<docs>/LOG.md`.

Research does not need a PoC, so a missing docs folder is fine. A half-migrated PoC does not block research either: give the answer first, and make the `Next:` line say to keep one layout.

1. **Check the setup.** Run `python3 "${CLAUDE_SKILL_DIR}/../poc-sources/scripts/spike_sources.py" status` and read the two lines it prints (sources file, agent). If the prerequisites check skipped `python3`, do not run it: treat the setup as not done and research public sources only, saying so in one line.
2. **First use, no internal sources yet** (the agent is MISSING). Tell the user in two lines: public research works now, and internal sources (wiki, drive, chat, email, meeting notes, local repos) need a one-time setup of about five minutes with `/spike-loop:poc-sources`. Ask with AskUserQuestion whether to research public sources only now or stop so they can run the setup first. If they stop, finish there with `Next: /spike-loop:poc-sources`. If they continue, do step 3 with `spike-loop:researcher`, and do not ask again in this session. If you cannot ask (a non-interactive run), continue with `spike-loop:researcher` and end your reply with one line: `Internal sources are not set up: run /spike-loop:poc-sources once.`
3. **Research.** Call the Agent tool once. Use subagent `researcher-internal` when the status shows it exists, otherwise `spike-loop:researcher`. If the call says `researcher-internal` is unknown, the user has not restarted since setup: say so and use `spike-loop:researcher` for this question. Pass the question verbatim and the repo root as an absolute path, say it has no conversation history, and tell it to follow the research-protocol skill and its output contract. Remind it to keep customer names out of outbound queries.
4. **Report.** Show the agent's answer as returned. If it says internal sources are not configured, point at `/spike-loop:poc-sources`. Then add one line starting `Next:`: if the answer changes an assumption in `<docs>/POC.md` (resolve the docs folder by the docs-folder rule above, and skip this if no PoC files exist), edit `<docs>/POC.md` and run `/spike-loop:poc-log`; otherwise build on it and run `/spike-loop:poc-verify` when there is something to check. In a non-interactive first use, put this `Next:` line before the `Internal sources are not set up` line, so that line stays last.
